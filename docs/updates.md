# Обновления: всё выкатывается само

Разработчик отправляет изменения в ветку `main` на GitHub. Дальше без участия человека
(GitHub Actions, workflow «Выкатка»):

1. **Автотесты** сервера, проверка типов и линтер приложения. Если что-то не так — дальше не идёт.
2. **Сервер.** Проверенная версия попадает в ветку `production`; сервер забирает её сам
   (см. «Автообновление» в [deploy.md](deploy.md)), предварительно сделав резервную копию базы.
3. **Приложение по воздуху** (EAS Update) — если менялась папка `mobile`. Публикуется только после
   того, как сервер обновился, чтобы новые экраны не обращались к старому серверу.

На телефонах приложение скачивает обновление при запуске и показывает внизу плашку
**«Загружено обновление — Перезапустить»**. В профиле есть строка **«Версия приложения»**
с кнопкой ручной проверки.

Ход выкатки виден на GitHub: вкладка **Actions** репозитория.

## Один раз: секреты для GitHub Actions

GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Что вставить |
|---|---|
| `EXPO_TOKEN` | expo.dev → аватар → **Account settings → Access tokens → Create token** |
| `GOOGLE_SERVICES_JSON` | всё содержимое файла `google-services.json` (открыть в Блокноте, Ctrl+A, Ctrl+C) |

Значения видны только GitHub Actions; ни в коде, ни в журналах их нет.

## Когда нужен новый APK

Когда меняется «нативная» часть: новое разрешение (камера, микрофон…), новый модуль телефона,
обновление версии Expo, смена `google-services.json`. Обновление, которому нужен новый APK,
на старую установку **не придёт** и ничего не сломает.

Сборка: GitHub → **Actions → «Сборка APK» → Run workflow**. Через 10–30 минут в итогах запуска
появится ссылка на APK. Разработчик запускает её сам и присылает ссылку.

## Что важно знать

- Обновление содержит только код и картинки приложения — данных участников в нём нет.
  Хранится на серверах Expo.
- Адрес сервера (`https://api.vectorfamily.kz`) записан в самом приложении.
- Бесплатный тариф Expo покрывает пилот; лимиты — на https://expo.dev/pricing.

## Если GitHub Actions недоступен — вручную

Сервер: `FORCE=1 /opt/kaktus/deploy/auto-update.sh` (берёт ветку `production`) или
`cd /opt/kaktus/deploy && docker compose up -d --build`.

Приложение: свежий ZIP, `google-services.json` в `mobile`, затем в `cmd` в папке `mobile`:

```bash
npm install
```

```bash
set EAS_NO_VCS=1
```

```bash
npx eas-cli@latest update --channel preview --environment preview --message "Что изменилось"
```
